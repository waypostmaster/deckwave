## Verdict

The engine, the UI and the extensions are in good shape for a public 0.8.0:
the escaping discipline holds everywhere a filename or a remote string
reaches the DOM, the postMessage surface is strictly same-origin, the
plan-token and in-place-order contracts are sound, and nothing in the
claims list is violated on screen except one already-known case (ledger 82,
now on four surfaces). Three things need attention in order:

1. **`tools/serve.py` serves `.git` through NTFS short names** — the one
   critical finding, reproduced live. Under `--lan` this exposes the
   private `master` history that the launch rule exists to protect.
2. **The handover timer runs on the wall clock while `pause()` freezes the
   audio clock** — a pause longer than the remaining track walks the deck
   state ahead of the audio (ledger 33's class, from a new mechanism).
3. **Handed-over decks are never disconnected and the worklet keeps them
   alive** — memory grows per handover; also a candidate mechanism for the
   §7 popping question (if gaps grow with handovers, not rate).

## Critical

### C1 — serve.py deny-list is bypassed by NTFS 8.3 short names [CONFIRMED]

> **FIXED LOCALLY 2026-09-01, uncommitted (keeper's instruction: fix and
> add the check, no commit).** `_forbidden()` now resolves with `realpath`
> and refuses NUL paths; `tools/check-serve.js` (22 checks) starts the real
> server and demands 403 on the aliases — it failed 8 of 22 against the old
> source. The 8777 listener was an orphan from 2026-08-18 and was replaced;
> `/GIT~1/HEAD` is 403 there now. Ledger 122. The published `serve.py` on
> GitHub still has the hole until a push.

`tools/serve.py:122-129` — `_forbidden()` tests `relpath().lower()` of the
translated path against the dotted rule and `DENY_DIRS`. NTFS gives every
long name an 8.3 alias (`.git` → `GIT~1`, `.claude` → `CLAUDE~1`,
`deckwave-patches` → `DECKWA~1`, `.citywalk-denylist` → `CITYWA~1`,
`.helm.json` → `HELM~1.JSO`). The alias starts with no dot and is not in the
deny set, so the check passes and `open()` follows the alias.

Reproduced on a scratch port with the current source:

| request | status |
|---|---|
| `/.git/HEAD` | 403 |
| `/GIT~1/HEAD` | **200** (`ref: refs/heads/public`) |
| `/GIT~1/config` | **200** |
| `/CITYWA~1` | **200** (the denylist — "names that must never appear in a shipped file") |
| `/tools/serve.py` | 403 |
| `/docs/RUNBOOK.md` | **200** (see M10) |

`/GIT~1/objects/…` and the packfiles are reachable the same way, so under
`--lan` the whole local history — including `master`, which the publishing
rule says must never leave the machine — is one HTTP request away from any
device on the network. Same family as ledger 120 (Windows name semantics);
no existing row.

**Fix shape (not a threshold):** `_music_path()` at `serve.py:98-101`
already resolves with `os.path.realpath()` before comparing to the root;
`_forbidden()` never got the same line. `realpath` expands short names on
Windows (verified: `…\GIT~1\HEAD` → `…\.git\HEAD`). **Gate:** a check that
requests `/GIT~1/HEAD` and demands 403 — it fails today. Note the server
already running on 8777 predates any fix and must be `--stop`ped to pick
one up (CLAUDE.md already records that hazard).

## High

### H1 — Handover timer on the wall clock, audio clock suspended [CONFIRMED]

`assets/deckwave.js:1372` arms `chainTimer = setTimeout(() => handover(ni),
(out - ctx.currentTime) * 1000 + 100)`. `pause()` at `:1470` calls
`ctx.suspend()`, which freezes `currentTime` but not the timer. There is no
`statechange` handler anywhere in `assets/` (grep: zero).

Scenario: a track at 100 s of 240 s, exit planned at 224 s; the keeper
pauses (or an Android call fires DWPHONE `calls`, ledger 71) for longer
than 124 s. The timer fires mid-pause: `idx = ni; A = B; B = null; chain()`.
`DW.nowMeta`, the card, `state.idx`, the route panel all now name the NEXT
track while the paused one is what will resume; `handed.at` is stamped
from the frozen clock; `chain()` decodes and schedules the next-next deck
and arms its timer early by the length of the pause, so a long pause walks
several steps ahead. Audio itself resumes correctly (source starts are on
the audio clock); the STATE is what runs ahead, which is exactly the class
the route panel's `LIST ≠ DECK` line was built to catch — and it will show
red.

Not in the ledger (78/89/114/117 cover pause/resume UI, not the timer).
Fix shape: on `statechange` back to `running`, re-arm from the audio clock
(or have the timer callback check `ctx.currentTime >= out` and re-arm if
not). No harness can see it: `handover` is only ever fired by hand.

Side note for LISTENING §8: only one deck is ever scheduled ahead, so if a
locked phone freezes main-thread timers, the set ends after the scheduled
deck. §8 should listen for a SECOND handover under lock, not just a new
title.

### H2 — Deck chains never disconnected; worklet keeps every deck alive [INFERRED]

`makeDeck` (`deckwave.js:1005-1016`) connects `src → st → lo → mid → hi → g
→ master`. `handover` (`:1378-1395`), `cancelPending` (`:1088-1104`) and
`stop()` (`:1428-1434`) never call `disconnect()`; the only two
`disconnect` calls in the file belong to `outputStream`. The vendored
processor's `process()` always returns `true` (keeps itself alive), so per
the Web Audio spec every `AudioWorkletNode` ever made is actively
processing for the life of the context. `st.port.onmessage` (`:1016`)
closes over the deck, so `d.src.buffer` — the decoded AudioBuffer, tens of
MB per track — stays reachable. The comment at `:1392`, `A.track.buf =
null; /* release behind */`, releases the meta's reference only; ledger
109/113 shape (a comment asserting a release the code does not perform).

Falsifier: task-manager RSS or a heap snapshot after five handovers on
desktop; a step of roughly one decoded track per handover confirms it.
Also a candidate discriminator for §7 (ledgers 65/69/81): if gaps grow with
the number of handed-over decks in a session rather than with rate, this
is the mechanism. Fix shape: after `out + fade + 0.4`, disconnect the
handed-over deck's gain, null `st.port.onmessage`, drop `d.src`.

### H3 — The card's attribution link is rebuilt every frame [INFERRED]

`assets/deckwave-nowplaying.js:284-290` assigns `$('npM').innerHTML`
(containing the `<a … ↗>` linkout) inside `update()`, which is called
every rAF (`:3`, `:162`; confirmed by reading). A click spans ~100 ms
between mousedown and mouseup; the anchor under the pointer is replaced
several times in that window, so the click resolves to the parent and no
navigation happens. This is ledger 94's shape (innerHTML every frame made
tooltips physically unopenable) on the surface the keeper asked for ("we
need a linkout button to the places serving the music"). CLAUDE.md records
the card *reading* `☉ Iwu · CC BY-NC-SA 3.0`, never a click.

Falsifier: play a libre track, click ↗ mid-set; if it opens, this is
wrong. Fix shape: write `npM` only when the composed string changes (the
`npT` path already uses textContent).
